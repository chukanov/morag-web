# Своя запись — на сайт: транскрибация у себя, сборка на сервере

Режим для установки **без сервера с моделями**: у сайта есть только BFF и движок поиска, а
транскрибация (диаризация, whisper, LLM-стадии) и экран из видео (Vision) идут на ноутбуке того,
кто загружает запись, — на Mac с Apple Silicon, через его собственный ключ к LLM-шлюзу. Сервер
получает пакет и доводит его до записи тем же путём, что и запись владельца корпуса.

```
Mac докладчика                                  сервер сайта
─────────────────────────────────────────       ──────────────────────────────────────
видео ─► ffmpeg ─► стек morag (asr-adaptor)     /api/ingest: манифест, файлы, finish
         └─► artifact.json (речь, слова)    ─►  incoming/<id>/ (стейджинг, вне records/)
         └─► voices.json (отпечатки CAM++)        ├─ узнавание голосов по реестру → номера корпуса
видео ─► slides_from_video, intro_frame,          ├─ видео → архив (media: Uploads/<id>.mp4)
         describe_slides (Vision),                ├─ make_record с настоящими словарями и раскладкой
         screen_refs, make_annotations       ─►   ├─ сайдкары экрана, кадры, слайды → records/…/<id>/
         └─► record.{slides,refs,annotations}     ├─ after: доразметка, обложка, снимок голосов
             + slides.zip                         └─ поиск: плановой индексацией (обычно ночью)
```

## Установка (один раз, Mac на Apple Silicon)

Два пути, и они для разных людей.

**С сайта — тому, кто просто хочет выложить запись.** Сайт раздаёт готовое зеркало (см.
«Раздача с сайта» ниже): страница `/ingest` даёт файл для двойного щелчка и строку

```bash
curl -fsSL https://site.example.org/api/ingest/get/<пропуск>/install | sh
```

Она ставит всё в `~/morag-ingest`: портативный python 3.12 (распаковкой, не установкой),
статический ffmpeg, снимок инструментов и движка, модели и приложение
`~/Applications/Загрузить запись.app`. **Ни Homebrew, ни прав администратора, ни учётки на
Hugging Face** — модели приезжают с сайта. **Ключ к шлюзу вписывать тоже не нужно:** стадии с
LLM идут в шлюз ЧЕРЕЗ САЙТ, а удостоверением служит та же сессия, которой человек вошёл (см.
«LLM через сайт»). Свой ключ остаётся запасным ходом в настройках приложения.

**Из репозитория — тому, кто платформу дорабатывает:**

```bash
git clone https://github.com/catonmoon/morag-web && cd morag-web
./tools/ingest-install.sh          # brew: ffmpeg, python; чекаут morag рядом; стек; модели; video-venv
export PATH="$HOME/asr-stack/bin:$PATH"
morag-ingest login --site https://site.example.org
```

Здесь модели качаются с Hugging Face: whisper и CAM++ публичные, **pyannote** — под вашим
токеном, после принятия условий на странице модели. Установщик спрашивает адрес LLM-шлюза,
модель, ключ и токен и пишет их в `~/.asr-stack.env` (0600).

В обоих случаях наминг голосов выключен (`ASR_ENABLE_NAMING=0`): имена ставят на сайте.

### Ключа к шлюзу у человека нет

Стадии с LLM (глоссарий, финал-раунд, описание кадров Vision) идут с машины докладчика в
LLM-шлюз — и раньше для этого нужен был его собственный ключ: завести, скопировать, вписать.
Теперь не нужен: **эти стадии ходят через сайт, а удостоверением служит та же сессия**, которой
человек вошёл, чтобы загрузить запись (`app/api/llm.py`, ручка `/api/ingest/llm/chat/completions`).
Приложение после входа само кладёт в файл стека адрес этой ручки, модель и строку сессии как
`OR_KEY` — стек умеет только `Authorization: Bearer <строка>`, и этого хватает.

Что это даёт, помимо удобства:

- **работает, пока человек залогинен**, и отзывается тем же движением, что «разлогинить везде» —
  удалением снимка учётки; убрали из группы доступа — доступ кончается на первом же запросе;
- ключа нет ни в приложении, ни на диске у человека — нечему утечь и нечего «вшивать»;
- видно, кто и сколько потратил: каждый вызов — строка журнала с логином.

⚠️ Форма запроса остаётся OpenAI-совместимой: её диктует адаптер морага, и менять чужой
публичный движок ради этого дорого. Поэтому ручка живёт **под загрузкой записи** и под её правом
(`ingest`), а не как «LLM сайта». Два рубежа при ней — не про безопасность: потолок
одновременных запросов одного человека (BFF это один процесс; без него расшифровка заткнула бы
живым посетителям `/api/ask`, а лишние запросы ЖДУТ очереди, а не падают) и строка в журнал.

Запасной ход остался: «у меня свой ключ» в настройках приложения (и `OR_KEY` в файле стека для
тех, кто гоняет стек вообще без сайта) — тогда стек ходит в шлюз напрямую.

## Загрузка: окно приложения

`morag-ingest app` (или ярлык, который делает установщик) открывает **окно**: перетащите в него
видео — название подставится из имени файла, дата из даты файла, остальное скрыто под
«подробнее». Дальше полоса прогресса по шагам (звук → расшифровка → экран → загрузка → сервер) и
карточка с ссылкой на готовую запись. Ключ к LLM-шлюзу вводится там же, в «настройках»: он
пишется в файл стека (0600), а поднятый стек гасится, чтобы адаптер перечитал ключ.

Окно — `WKWebView` в нативном окне (PyObjC, `tools/requirements-app.txt`), внутри та же страница,
что и в браузере. ⚠️ Перетаскивание перехватывает наш подкласс `WKWebView`: иначе WebKit
открыл бы брошенный файл вместо страницы. Нет PyObjC (не мак) — `app` открывает браузер.

⚠️ Окно живёт, пока жив процесс: закрытие во время работы спрашивает подтверждение. Свернуть —
можно, закрыть — прервать расшифровку.

## Загрузка: страница в браузере

`morag-ingest ui` — то же самое, но страницей в браузере (это локальный сервер на `127.0.0.1`,
наружу он не смотрит; адрес с токеном печатается в терминале). Годится там, где окна нет.
Перетащить файл в браузер тоже можно: пути браузер не даёт, поэтому файл ищется по имени и
размеру среди Загрузок, Рабочего стола и Movies — не нашёлся, выбирается из списка.

⚠️ Видео **не загружается в браузер** — конвейер читает файл с диска; копировать гигабайты
через localhost незачем. ⚠️ Страница требует токен из адреса и отвергает чужой `Origin`: петля
сама по себе не защищает от вкладки постороннего сайта, открытой в том же браузере.

## Загрузка: командная строка

Та же работа без страницы:

```bash
morag-ingest run talk.mp4 --title "Kafka без боли" --date 2026-03-12 \
    --event "Доклады" --speakers "Мария Кузнецова" --summary "О чём" --slides deck.pdf --stack
```

`--stack` поднимает стек транскрибации перед работой и гасит после (иначе — `stack.sh up`
руками). `--event` — из списка сайта (`morag-ingest options`): рубрика решает ветку и место
записи по правилам раскладки корпуса; без правил — любая. `--speakers` попадают в шапку
докладчиками, если у ветки модель `talk`. `--no-screen` — без экрана из видео (втрое быстрее,
но поиск не увидит слайды). Сколько ждать на M-серии: час записи ≈ 10–15 минут транскрибации,
~5 минут экрана, загрузка видео — по сети; на сервере сборка секунды. Индексации человек НЕ
ждёт: запись читается на сайте сразу, а в поиск она попадает плановым прогоном (`ingest.index`
пуст → отвечает cron сервера, обычно ночью). Статус приёма так и говорит: `search: now|later`.

Каждый шаг возобновляем: упало — запустите ту же команду, продолжится с упавшего
(`~/morag-ingest/<id>/state.json`; артефакт и экран не пересчитываются, отданные файлы не
льются заново). `morag-ingest status <id>` — что с записью на сервере.

## Что получится и чего не будет

- Запись на сайте: расшифровка с караоке, видео из архива, экран в поиске (если снят), докладчики
  из `--speakers`, аннотация из `--summary`. Адрес печатает `run`.
- **Голоса узнаёт сервер** — и человек, говоривший в других записях корпуса, приезжает под
  СВОИМ номером, с уже названным именем. Метки вашей машины при этом ничего не значат: у неё
  свой счёт голосов, поэтому приложение кладёт в пакет отпечатки (`voices.json`), а номера
  раздаёт реестр сайта (см. «Узнавание голосов»). Незнакомый голос заводится и остаётся
  безымянным `Speaker_N`; назвать: «Это я» у своего голоса в режиме правки, остальных — админ
  карточкой голоса.
- Категория, темы и — если названия не дали — заголовок появляются САМИ, до индексации
  (`ingest.enrich`, `tools/auto_meta.py`): их ставит сервер ключом корпуса. Выключено — как
  раньше, плановой разметкой.
- Сырой артефакт едет на сервер и лежит в записи (`record.json`) — правка реплик на сайте работает.

## Узнавание голосов: номера раздаёт сервер

`Speaker_N` — не метка внутри записи, а **идентификатор из реестра голосов**: имя, названное
один раз, относится ко всем записям, где голос звучит. Реестр — это состояние, слить два реестра
нельзя (провенанс не различает записи), поэтому хозяин у него ОДИН — сервер. У машины докладчика
свой счёт голосов, и её `Speaker_3` не имеет к корпусному никакого отношения.

Как это работает: приложение после расшифровки считает **отпечатки** голосов (локальный CAM++,
`tools/voiceprints.py`: спаны реплик из артефакта → wav 16 кГц → центроид на голос) и кладёт их
в пакет отдельным файлом `voices.json`. Сервер при приёме зовёт своё же узнавание
(`app/content/registry.py`) и переписывает метки настоящими номерами корпуса — теми, под
которыми этих людей уже знают другие записи.

Решение простое и всё целиком в `identify()`: косинус центроида со всеми центроидами всех
голосов реестра (векторы L2-нормированы, косинус = скалярное произведение), дальше три исхода.

| косинус | что делаем | почему так |
|---|---|---|
| ≥ `match_threshold` (0.75) | это он: отдаём его номер, дописываем центроид (потолок 8) | несколько центроидов на голос — это разные микрофоны и годы |
| `suspect` … `match` (0.65–0.75) | **новый голос**, но с пометкой `similar_to` | на 0.617 в живом корпусе сидели РАЗНЫЕ люди; склеить двоих необратимо, развести — правится словарём |
| ниже | новый голос | — |

- ⚠️ **Голоса разбираются по убыванию эфира.** Номера должен получать сперва тот, кто говорил
  дольше: у долгого голоса центроид крепче, и именно он задаёт, к кому потом притянутся короткие.
- ⚠️ **Короткий голос (< `short_air_min`, 15 с) тоже получает свой номер** — и метку `short`.
  Раньше такие приклеивались к ближайшему БЕЗ порога, и вопрос из зала на десять секунд
  становился докладчиком; метка нужна, чтобы верстак голосов не зарастал десятисекундными.
- ⚠️ **Битый файл реестра — отказ вслух (503), а не «начать с нуля».** Пустой реестр начал бы
  нумерацию заново и подписал бы чужими именами весь корпус; рядом всегда лежит `.bak`.
- ⚠️ **Запись идёт под `flock`** + `.bak` + `.tmp` с `os.replace`: два приёма разом иначе
  поделили бы один `next_id`, и один номер достался бы двум людям.

Ручки (право `ingest`, то же, что у загрузки — узнавание и есть часть приёма; отдельной
«регистрации голоса» не существует, регистрировать без отпечатка нечего):

| ручка | зачем |
|---|---|
| `POST /api/voices/identify` | `{episode, voices: {метка: {centroid, air_sec}}, dry?}` → `{map, report}` |
| `GET /api/voices/registry` | сколько голосов, `next_id`, когда менялся — для проверки доставки |

⚠️⚠️ **`dry: true` — не украшение.** Узнавание ПИШЕТ: новый голос занимает номер, узнанный
получает центроид. Предпросмотр без этого флага оставил в реестре четыре голоса записи, которую
ещё не решили трогать (ловилось на первой же живой перенумерации 24.09). Отчёт при `dry` тот
же, номера — те, что будут заняты.

⚠️ **Реестр лежит ВНЕ корпуса и вне доставки** (`voices.registry` в конфиге — например
`~/state/speaker_registry.json`): это биометрия. В git его нет, `rsync --delete` до него не
дотягивается, коллегам он не раздаётся никогда. Путь пуст → узнавание выключено, и метки
разводятся в отдельный диапазон, как раньше.

**Запись, собранная мимо приёма** (свежий прогон на своей машине, или принятая до того, как
узнавание появилось), приводится к корпусным номерам тем же путём —
`tools/voices_assign.py <каталог записи>`: считает отпечатки, спрашивает у сайта карту,
переписывает сырой сайдкар и ссылки экрана. ⚠️ Он же переносит **имена**: голос, названный в
словаре под старым номером, после смены идентификатора осиротел бы МОЛЧА — `make_record` ищет
старую метку в тексте, не находит и идёт дальше.

## Раздача с сайта: зеркало, пропуск, страница

Чтобы установка не требовала ни brew, ни учёток, сайт раздаёт **зеркало** — каталог
`ingest.dist_dir` рядом с корпусом: портативный python (`python-build-standalone`), статический
ffmpeg (из колеса `imageio-ffmpeg`), снимок `tools/`, снимок движка транскрибации, модели
(whisper, CAM++, pyannote, MMS_FA) и настройки корпуса. Содержимое готовит владелец корпуса
своим инструментом (у нас — `build_dist.py` в приватном репозитории) и кладёт рядом с сайтом;
опись — `manifest.json` (её читает страница) и `manifest.sh` (её читает установщик: на чистом
маке нечем разобрать JSON, системный `python3` там — заглушка Xcode).

Ручки (`app/api/ingest.py`, `app/content/dist.py`):

| ручка | кому | зачем |
|---|---|---|
| `GET /api/ingest/dist` | вошедшему с правом `ingest` | что лежит на зеркале, строка установки, пропуск |
| `GET /api/ingest/app.zip` | ему же | zip с `.command` — путь «двойным щелчком» |
| `GET /api/ingest/get/<пропуск>/install` | кому угодно с пропуском | `tools/install-mac.sh` с подставленными адресом и пропуском |
| `GET /api/ingest/get/<пропуск>/file/<имя>` | ему же | файл зеркала, с `Range` |

⚠️ **Пропуск вместо сессии.** Ставится всё строкой в терминале, а у `curl` cookie сайта нет и
быть не должно: сессия сотрудника в истории shell — плохая идея. Пропуск подписан ключом,
ВЫВЕДЕННЫМ из ключа сессий (`AuthService.derived_secret`), живёт неделю и даёт ровно одно право
— брать файлы этого каталога. Поэтому и только поэтому `/api/ingest/get/…` открыт на рубеже
входа (`PUBLIC_PREFIX`), а `/api/ingest/dist` и `app.zip` — нет.

⚠️⚠️ **Скачанный файл двойным щелчком не запустится — вообще.** Замерено 23.09 на macOS 26:
`spctl` отвечает «rejected, no usable signature», а человек видит «Apple не удалось подтвердить,
что файл не содержит вредоносного ПО» — и в диалоге только «Переместить в Корзину» и «Готово»,
кнопки «открыть всё равно» там НЕТ (она спрятана в «Системные настройки → Конфиденциальность и
безопасность», отдельным походом). Трюк с документом `.terminal` macOS 26 тоже блокирует.
Из Терминала ТОТ ЖЕ файл с той же меткой карантина запускается без единого вопроса (проверено).
Поэтому:

- **основной путь — строка `… | sh`**: браузер в нём не участвует, карантина нет ни на чём;
- файл остаётся запасным, и его имя само говорит, что делать: «Установить — перетащите в
  Терминал.command»;
- **собранное установщиком приложение Gatekeeper не проверяет вовсе** — карантин вешает тот, кто
  СКАЧАЛ файл, а `curl | sh` не помечает ничего. Ad-hoc-подпись (`codesign -s -`) карантин не
  снимает: она нужна, чтобы macOS не считала приложение новым после каждого обновления и не
  спрашивала доступ к папкам заново;
- настоящий двойной щелчок по скачанному дала бы только подпись с нотаризацией в Apple (аккаунт
  разработчика, 99 $ в год) — решение владельца, пока не заводим.

⚠️ **`curl` в строке установки — системный (`/usr/bin/curl`), и это не педантизм.** Сертификат
корпоративного сайта подписан внутренним центром сертификации: `/usr/bin/curl` спрашивает связку
ключей машины (там корпоративный корень есть), а `curl` из conda или brew носит с собой только
публичные корни и отвечает «unable to get local issuer certificate». Ловилось на первой же живой
установке — у владельца первым в `PATH` оказался curl из anaconda.

⚠️⚠️ **Той же болезнью болеет питон.** `httpx` и `pip` верят только `certifi`, поэтому приложение
не смогло бы войти на сайт (`CERTIFICATE_VERIFY_FAILED` — выглядит как «сайт не отвечает»).
Лечится в двух местах: установщик собирает `ca-bundle.pem` из публичных корней плюс связка
ключей машины и называет его в `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE` окружения стека (его читают
и наши инструменты, и адаптер движка, и pip), а в чекауте разработчика то же делает пакет
`truststore` (`tools/ingest.py` подключает его, если он есть). ⓘ Прокси из окружения клиент
игнорирует (`trust_env=False`): сайт и стек внутри периметра, а корпоративный прокси отвечает на
них 503.

⚠️ **`ffprobe` в зеркале нет** — статической сборки под arm64 нет ни в одном колесе PyPI.
Свойства видео там читает `av` (PyAV), см. `slides_from_video.probe`; где `ffprobe` стоит,
поведение прежнее.

Страница `/ingest` (пункт «Загрузить свою запись» в меню пользователя, виден по праву `ingest`)
показывает обе дороги, размер, сколько ждать и срок жизни ссылки. Зеркала нет — страница
честно говорит об этом, а не показывает пустоту.

## Сервер: что включить

`app/config.yml` корпуса, блок `ingest` (см. `app/config.example.yml`): `enabled: true`,
`archive` — корень архива видео, тот же, что раздаёт `media_base`; `video_dir` — подкаталог под
загрузки; `build` — `make_record` из venv сайта; `after` — обложка и снимок голосов; `index` —
команда индексации (у docker-compose — `indexer … index`); `min_free_gb` — сколько места
оставлять; `enrich: true` — доразметка принятой записи; `dist_dir` — каталог зеркала для
раздачи приложения; `index` ПУСТОЙ — приём не индексирует, это делает плановый прогон (у нас
cron, ночью: индексатор всё равно синхронизирует корпус целиком по mtime, поэтому один прогон
подбирает всё, что накопилось за день, а человек не смотрит 20–40 минут в «идёт индексация»); `llm` — шлюз для расшифровки на чужом маке (включён по умолчанию, работает,
если настроен `topic` с ключом). Право `ingest` — любой вошедший (`app/auth/roles.py`); без входа — только петля.
Блок `voices`: `registry` — путь к реестру голосов (вне корпуса!), `match_threshold`,
`suspect_threshold`, `short_air_min`, `max_centroids` — пороги узнавания.
Стейджинг `<семья>/incoming` — вне `records/`, индексатор его не видит; в git корпуса и в
доставку он не входит. ⚠️ Если корпус живёт в git на другой машине, записи, принятые сервером,
надо забирать ОТТУДА (у нас — `deploy_server.py pull-records` перед `push`), иначе следующая
доставка с `--delete` их снесёт.

Обратный прокси: тело PUT идёт потоком, лимита на размер у BFF нет (кроме `max_gb`); у apache
2.4 `LimitRequestBody` по умолчанию без лимита, таймаут чтения — на минуты, как у `/api/ask`.
