# Формат записи

Единица корпуса — **запись** (доклад, лекция, собрание): каталог на диске, имя каталога — её
идентификатор и адрес страницы (`2026-03-12-kafka-bez-boli` → `/<слаг>/rec/2026-03-12-kafka-bez-boli`).

```
records/<ветка>/<второй уровень>/<id>/
  record.md                 шапка + реплики с тайм-кодами        — обязателен
  record.words.json         слова с временами (караоке, перемотка) — обязателен для караоке
  record.meta.json          авторское знание о записи с провенансом
  record.annotations.json   экран из видео: смены слайдов, содержимое, обращения «вот здесь»
  record.slides.json        шкала экрана и кадры (сырец аннотаций), обложка карточки
  record.refs.json          обращения к экрану (сырец аннотаций)
  slides/sNNN.jpg           кадры слайдов (вне git; нужны сайту для обложки и таймлайна)
  slides.pdf                презентация, если есть
  record.json               сырой сайдкар адаптера транскрибации (вне git; нужен для правок)
```

Почему каталог, а не «сезон/выпуск»: каталог уникален по построению, группировка — обычное
строковое поле `event`, а поздно загруженная запись не ломает нумерацию.

## `record.md`

Шапка — YAML между `---`, дальше реплики: `[Имя] <!-- t:12.3 --> текст`. Пустая строка — новый
абзац, и это **не оформление, а тайм-код**: чанкер движка вычисляет время внутри реплики
интерполяцией по позиции в тексте (замерено: ошибка до 110 с), а абзац со своей мереной меткой
это снимает. Реплика режется по концу предложения (сокращение вроде «т.е.» концом не считается:
следующее слово обязано начинаться с заглавной или цифры); запасное правило — самая длинная
пауза. Собирает `tools/make_record.py`.

| поле | обязательно | что |
|---|---|---|
| `title`, `date` | да | название и дата (у доклада — дата выступления, не публикации) |
| `year` | | год записи; у лекций курса — год **курса**, не выкладки |
| `event` | | рубрика / название встречи или курса — группировка списка |
| `branch` | | ветка (каталог первого уровня); пишется С ДИСКА, не из правил — истина там, где файл |
| `kind` | | формат: доклад, воркшоп, демо, лекция курса… |
| `category`, `topics` | | предмет (одна категория) и темы из таксономии корпуса |
| `speakers` | | ВЫСТУПАВШИЕ: готовили и читали доклад, лектор курса |
| `participants` | | остальные НАЗВАННЫЕ: открыли встречу, вели, спрашивали из зала |
| `voices` | | голосов всего, включая безымянные `Speaker_N` |
| `duration_sec` | | длительность |
| `summary` | | авторская аннотация (из поста/анонса); без неё сайт берёт `blurb` из меты |
| `media` | | видео: имя файла или путь внутри архива (`media_base` в конфиге сайта) |
| `slides`, `post`, `discussion` | | презентация, ссылка на исходный пост, ссылка на обсуждение |
| `tags` | | метки исходного поста, разнородные |

⚠️ **Поля шапки уезжают в payload каждого чанка** и кормят инструмент `catalog` агента («кто
выступал на встрече X»). Их правка — переиндексация записи; аннотация сайта (`blurb`) поэтому
живёт в мете. Запись **без видео** (анонс) обязана показываться, а не выпадать.

⚠️ `Speaker_N` — идентификатор из **реестра голосов** адаптера, общий на весь корпус: имя,
названное один раз (словарь `names.json`), относится ко всем записям, где голос звучит. В шапку
безымянные не идут; в ответ агента и в титры — тоже.

## `record.words.json` (`morag-words-v1`)

```json
{"format": "morag-words-v1", "duration_sec": 152, "aligned_by": "mms_fa",
 "turns": [{"start": 0.0, "end": 6.4, "speaker": "Мария Кузнецова", "speaker_id": "Speaker_3",
            "words": [["Всем", 0.0, 0.3], ["привет.", 0.35, 0.9]]}]}
```

Слово хранится **вместе со своим временем**, а не индексом в тексте: правка расшифровки иначе
молча сдвинула бы всю подсветку. Порядок слов по времени — обязательство перед фронтом
(караоке ищет текущее слово двоичным поиском); дыра во времени = потерянная речь, она остаётся
честной дырой, а не маскируется сдвигом соседей. Абзацы здесь те же, что в `record.md`:
хранение и отображение склеены намеренно.

## `record.meta.json`

Что известно о записи помимо расшифровки, каждый факт с `from` (откуда): `owner` (рука
владельца, окончательно) > `calendar` (календарь выступлений) > `corpus` (канон словаря) >
`slide` > `tag` > `post` > `audio` (самопредставление — только по сырым репликам). Ключи:
`title`, `speakers[{name, from, full?, note?}]`, `roles{speakers, participants}` (рука
владельца, инструмент не трогает), `terms[{term, from}]` (подсказки транскрибации),
`summary{text, from}`, `blurb` (сводка сайта для записей без авторской), `links{post,
discussion, materials[]}`, `classification` и `labels` (классификатор и рука владельца по
таксономии). ⚠️ Кольца «шапка → мета → шапка» нет: мета имена из шапки не читает.

Плоский список подсказок для адаптера (`<id>.hints.json`) строится из меты + правая часть
`text_fixes.json` всего корпуса: внутренние термины лежат в презентации только той встречи, где
они тема, а произносят их всюду.

## `record.annotations.json` — экран из видео

`{"version", "record", "source", "items": [...]}`; три рода элементов:
- `screen` — отрезок экрана `{t0, t1, kind (slide|app|browser|terminal|…), label, sub, text, frame}`;
  текст окна программы режется (300 знаков): это «что было на мониторе», а не авторский слайд;
- `boundary` — `{at}` смена темы: подсказка чанкеру, граница притягивается к концу предложения;
- `ref` — `{at, to, quote, text}` обращение «вот здесь» и к какому экрану оно относится;
  привязка сильнее окна: граница не отделит предложение с обращением от его экрана.

Движок (ADR-0027 в мораге) кладёт экран в чанк рядом с речью (`payload[screen]`), подмешивает в
sparse/BM25 и печатает агенту «На экране (MM:SS, Слайд N «…»): …» перед репликами.
Сырцы — `record.slides.json` (шкала, кадры, описания Vision, обложка) и `record.refs.json`.
Подробно — `screen-layer.md`.

## Словари корпуса (в каталоге семьи)

- `names.json` — `speakers: {Speaker_N: "Имя Фамилия"}` (+ `records` для адресных правок,
  `_why` — кто и почему); форма «Имя Фамилия», фамилия — последнее слово.
- `text_fixes.json` — гарблы ASR `{was, now, why}` (`global` и по записям) и отдельный ключ
  `censor` (расслышано верно, но решено не печатать; замена — один токен без пробелов).
- `turn_fixes.json` — поместные правки реплик с сайта: `was` ищется как подряд идущие слова
  в сырце, не нашлось — правка не применяется и говорит об этом.

Правки применяются при сборке (`make_record.py --all` пересобирает корпус за минуту);
убранная строка отменяет правку. Файл пишется только если содержимое изменилось: индексатор
решает «изменился ли документ» по mtime.
