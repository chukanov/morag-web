# Экран из видео: второй слой записи

Доклад — речь ПРО то, что на экране; «вот здесь», «на этой схеме» — указательная речь, референт
которой в кадре, и для поиска такие места пустые. Цель — чтобы единица поиска несла оба слоя:
что сказано и что было на экране В ЭТОТ момент. Не OCR, а Vision-модель: кадр из ffmpeg →
описание. PDF презентаций не смотрим: какой слайд когда показывали, знает только видео.

## Конвейер (четыре инструмента, каждый — свой сайдкар)

```
slides_from_video.py   шкала экрана и кадры            → record.slides.json, slides/sNNN.jpg
describe_slides.py     описание кадров Vision           → record.slides.json (desc, desc_meta)
screen_refs.py         обращения к экрану + разрешение   → record.refs.json
make_annotations.py    аннотации для движка              → record.annotations.json
intro_frame.py         заставка (первый видимый кадр)    → record.slides.json (intro)
make_cover.py          обложка карточки                  → record.slides.json (cover)
make_blurb.py          сводка для записей без аннотации  → record.meta.json (blurb)
video_batch.py         всё это по корпусу; видео — локально или по ssh с сервера (ops.env)
```

Зависимости — `tools/requirements-video.txt` (numpy, scipy, pillow, httpx) и ffmpeg. Адрес и
ключ Vision/Instruct — файл стека транскрибации (`ASR_STACK_ENV`, `ASR_LLM_BASE_URL`, `OR_KEY`).

## Что замерено и почему так

- **Декодировать программно.** `-hwaccel videotoolbox` при выходе 320×180 в десять раз
  медленнее: узкое место — выгрузка кадров с GPU.
- **Маска не-содержимого строится из самого видео:** рамка «где хоть раз менялось много» плюс
  частые изменения медианой по отрезкам — иначе полоса участников даёт ложные смены слайдов, а
  область демо ослепляет детектор.
- **Тождество слайда — прямым сравнением кадров после нормализации**, не dHash (склеивал разные
  слайды одной вёрстки); показ в Jitsi/Meet перерисовывает область на 13–16 %.
- **Люди не описываются и не хранятся:** кадр с людьми удаляется (докладчик в кадре — второй
  вопрос Vision, `who: speaker` остаётся). **Экран демо ≠ слайд:** окно программы — «что было на
  мониторе», текст режется до 300 знаков; «не описали» ≠ «не сохранили».
- **Thinking у Vision выключать явно,** иначе свободный вопрос съедает весь `max_tokens`.
- **У webm из браузера успех вырезки кадра — по файлу, не по коду возврата.**
- **Сервер отвечает `200` с телом `null` под нагрузкой** — это повтор, как обрыв соединения.
- **Заставка — первый кадр:** правила «кадр уже неподвижен» и «яркость устоялась» уводили в
  середину кроссфейда; единственное движение вперёд — наплыв из черноты.
- **Обращение `slide` — индекс ПОКАЗА, а не номер слайда в колоде:** возвращающийся слайд
  показан несколько раз, и по номеру колоды привязки указывали на будущий показ.
- **Серверный режим** (`--remote`): детектор читает по ssh серый поток 320×180 от ffmpeg на
  сервере (поток в 20–50 раз меньше файла), кадры режутся там же — гонять видео по сети не надо.

## Как движок использует аннотации (ADR-0027 в мораге)

Смена слайда — **подсказка границы** чанка с притяжением к концу предложения, не нож по клику;
привязка «слова в `at` относятся к экрану `to`» сильнее окна; отрезок короче 60 токенов клеится к
соседу. Экран — поле чанка (`payload[screen]`) по отрезку, подмешивается в sparse и BM25, справка
контекста получает блок «На экране:», реранкер и выдача печатают `На экране (MM:SS, Слайд N
«…»): …` перед речью. Отдельный вектор экрана и нога RRF **не нужны** (замерено: тянут короткие
титульные слайды). Замер на семи записях: ходов агента 82 → 39, в ответах то, чего в речи нет
(строка кода, элементы схемы), речь не просела; цена — +60 % чанков.

⚠️ `slides.md` (документ экрана рядом с `record.md`) — не делать: индексатор берёт все `*.md`
каталога, и экран шёл бы в индекс вторым рядом с полем чанка. Человеку экран читать —
`record.slides.json` и кадры.

## Обложка карточки

`make_cover.py` выбирает кадр детерминированно, без модели: слайд, чей заголовок лучше всего
совпал с названием (обычно титульный), иначе заставка, иначе первый авторский слайд ≥ 10 с,
иначе самый долгий; рука владельца — `"by": "owner"`, не трогается. Сайт отдаёт кадры по
`GET /api/records/<id>/frame/slides/sNNN.jpg` (белый список `slides/*.jpg`) и показывает их
через рамку `cover.crop.box`; слайдшоу на карточке — `GET /api/records/<id>/frames`.
