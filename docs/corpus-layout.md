# Раскладка корпуса: витрина, пространства, ветки

Корпус — каталог, на который указывает `corpora[].dir` в `app/config.yml` (или
`MORAG_WEB_CORPUS`). Это либо **одно пространство** (лежит `site.yml`), либо **витрина
пространств** (лежит `hub.yml`). Одно правило покрывает оба случая: витрина при единственном
пространстве вырождается в переход внутрь, и заказ с одним корпусом работает без строчки
особого кода. Шаблоны — `corpora/example/`.

```
<семья>/
  hub.yml            витрина: бренд сайта, порядок пространств, правила раскладки, роли
  brand/             картинки бренда: обложка, значок, рисунок знака (mark.txt)
  names.json  text_fixes.json  turn_fixes.json     словари правок — общие на все пространства
  voices.json        снимок голосов (производный, вне git)
  taxonomy.yml       категории и темы для классификатора
  asr-profile.env    профиль транскрибации (качество; в git), ops.env (хозяйство: машины, порядок веток)
  inbox/             что ждёт транскрибации (вне git)
  spaces/<слаг>/
    site.yml         бренд, тема, чат (шаблоны вопросов, пресеты), порядок списка
    morag-config.yml движок: коллекции, LLM, эмбеддеры, чанкер, промпт агента (вне git; пример рядом)
    probes.yml       контрольные вопросы по классам ошибок
    records/<ветка>/<второй уровень>/<id>/…
```

## Пространство = свой поиск

Пространство — самостоятельный сайт: свой каталог записей (он же `sources[].path` индексатора),
свой процесс движка со своей парой коллекций, свой префикс в адресе (`/<слаг>/…`), свой
бренд и тема. Раздельный поиск — это физическое разделение, а не фильтр: в запрос к движку
уходят только `{model, messages}`, канала «искать в подмножестве» нет; каталог, на который не
смотрит ни один `sources[].path`, не попадёт в базу никак. Разделять стоит, когда корпуса
конфликтуют терминами или у них разный доступ; один круг людей и терминов — одно пространство
с ветками внутри.

Переход между пространствами — полная перезагрузка страницы: конфиг, индекс, плеер и история
чата у каждого свои. Слаг уезжает в каждый запрос к API (`useCorpus` в `web/js/api.js`).
Слаги `chat`, `records`, `rec`, `api`, `css`, `js`, `assets`, `voices`, `calendar`, `signin`
заняты роутером (`RESERVED_SLUGS` в `app/config.py` и `RESERVED` в `web/js/router.js` — тест
сверяет).

## Раздел — это каталог

`records/<ветка>/<второй уровень>/<id>/` — и другого источника правды нет: поля `branch` и
второй уровень читаются из пути. Список на сайте плоский, раздел, подраздел, год, метка и
спикер — фильтры (в адресе через `?section=…&year=…`). Второй уровень по умолчанию — год из
даты, но у курса год бесполезен: правило может назвать его буквально (`sub: "Python 2024"`).
Ось второго уровня у каждого раздела своя, полем шапки это не выразить, каталог выражает даром.

Что иерархия даёт движку: путь входит в dense-вектор чанка и в промпт реранкера (каталоги
названы по-человечески и кириллицей), а карта знаний получает осмысленные корни — ветки и
второй уровень. Чего не даёт: `find_section` ветку не увидит (родитель `record.md` — папка
записи), в BM25 путь не входит, в выдаче `search` агент путь не видит — поэтому ветка
продублирована полем `branch` в шапке.

⚠️ Переезд записи после индексации — её переиндексация (путь входит в `doc_id`), и карту
знаний надо пересобрать (`rebuild-km`), иначе она зовёт агента по адресам, которых нет.

## Правила раскладки — `hub.yml::routing`

Отвечают ровно на один вопрос: **куда положить новую запись**. Разложили — дальше истина на
диске; сайт правил не читает (единственный потребитель — `tools/spaces.py`).

```yaml
routing:
  - match: {tag: "Концерт", event_prefix: "Концерт"}   # ключи соединяются ИЛИ
    space: talks
    branch: "Встречи"
  - match: {event_prefix: "Курс"}
    space: talks
    branch: "Курсы"
    sub: "Python 2024"                                  # второй уровень буквально
  - match: {rest: true}
    space: talks
    branch: "Доклады"
```

Первое совпавшее правило выигрывает. Раскладку нельзя вывести из одного поля: запись может
лежать с рубрикой одной ветки и относиться к другой только по метке — поэтому такое правило
стоит первым, а ключи `match` — ИЛИ. Новый курс вписывается руками (второй уровень из рубрики
не вывести); пока правила нет, лекции уедут в запасную ветку — заметно в списке, не молча.
`.gitignore` корпуса завязан на глубину пути — проверять `git check-ignore -v` после переезда.

## Люди — по ролям (`hub.yml::roles`)

`speakers` — выступавшие, `participants` — остальные названные, `voices` — голосов всего.
Модель по ветке: `talk` — докладчики по календарю → по мете → самый долгий названный голос при
доле эфира ≥ 40 % (порог важнее полноты: без него докладчиком становился ведущий, открывший
встречу); `course` — лектор = самый долгий голос; `meeting` — все в участниках. Имена сходятся по
фамилии и имени с уменьшительными (`same_person`). Рука владельца — ключ `roles` в мете.

## Категории и темы (`taxonomy.yml`)

`category` — одна на запись, предмет; `topics` — список из словаря (канон написания с
алиасами: расшифровка коверкает названия, а здесь они выправлены); `kind` — формат; `year` —
отдельное поле. Классификатор (`tools/classify.py`) — у нас, не в движке: вход — сводка и
глоссарий из сайдкара, незнакомая тема уезжает в отчёт, а не в шапку. Таксономия — это и есть
промпт: разметку правят определениями категорий («НЕ про …»), а не промптом. Движок фильтрует
по этим полям (`search(filters=…)`, ADR-0026: значения — `enum` в схеме инструмента).

## Бренд и тема (`site.yml` / `hub.yml`)

`brand`: `title` (вкладка, форма входа, превью), `tagline`, `about` (HTML, `{записей}` —
живое число), `cover`, `favicon`, `mark` + `mark_face` (рисунок ASCII в шапке и клетки
мордочки), `wordmark` (слово рамочным шрифтом), `links`, `examples`. Пространство наследует
от витрины то, чего не задало. `theme`: `tokens` (акцент), `fonts`, `sections` (цвет ветки —
им запись маркируется везде; ветка без цвета остаётся в акценте сайта), `halo` (перелив знака).
`chat`: шаблоны вопроса из читалки и к одной записи, пресеты кнопок по веткам. `content`:
`order` и `section_order` (у курса — по возрастанию: лекции читают подряд).
